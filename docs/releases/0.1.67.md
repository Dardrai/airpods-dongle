# AirPods Dongle 0.1.67

Preserve the controller's working packet permissions during Game Mode, matching
the baseline-preserving policy in LibrePods Pixel145. This source also includes
the reviewed firmware-version report and generated protocol refactoring from
PRs 1 and 2.

## Changes

- Game Mode keeps the selected AirPods connection's controller-confirmed packet
  mask. It no longer adds `0x2204` to prohibit 3-Mbit EDR packets. A narrower
  controller-confirmed mask is preserved too; `CC18` is not assumed universally.
- The startup packet request, matching command status and terminal event remain
  required. Outstanding restoration, stale replies, changed peers, reused ACL
  handles, timeout and controller-reset fences stay in place.
- The normal 200 ms controller flush timeout, 60/150 ms receiver targets, finite
  clock adjustment, USB pitch-preserving transition, codec settings and volume
  behavior are unchanged.
- Read-only typed feature 24 reports the running CMake firmware version. The CLI
  exposes it through `python tools/airpods.py firmware`.
- The machine-readable protocol generates C, Python, Kotlin and Rust definitions.
  LibrePods Android and NTPods consume the exported constants and wire vectors
  through their existing production parsers. Offline checks pin both clients to
  the exported specification and reject edited or missing generated files.
- Hold actions use the existing macOS sender evidence: `1` Assistant and `5`
  Noise Control, with the right ear in the low byte and left ear in the next.
  The CLI retains left/right argument order. Both mixed choices keep their
  previous wire values; same-action choices and non-listening-model checks are
  corrected.

## Checks and limits

HCI regression tests assert no extra packet-policy writes on Game Mode On/Off,
including controller-clamped and DM1-normalized baselines. Failure, restoration,
credit priority, phone-ACL exclusion, stale-owner and reconnect tests remain.
Protocol generation, shared vectors and named hold-action tests cover the new
bindings and firmware-version report. Native sanitizer, ARM and linked codec/
memory checks must pass before packaging.

This is pending hardware acceptance. Pixel145's phone listening result does not
prove Pico radio performance, weak-signal behavior or acoustic latency. Test
Game Mode On/Off, pause/resume, both-bud return, host/stem volume and reconnect
before calling the firmware accepted. No new hardware result is claimed here.
