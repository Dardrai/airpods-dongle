# AirPods Dongle 0.1.69

Allow USB servicing during Game Mode preparation and keep explicit takeovers
alive through passive status updates from the previous owner.

- Release PCM exclusion between bounded peak-scan and snapshot chunks, allowing
  the USB timer to service the single-buffered audio OUT endpoint.
- Revalidate encoder ownership and original source identity after each yield.
  A reset, new source or overwritten history cancels stale work before consumption.
- Keep post-read scope validation, clock debit and job publication atomic.
- Refresh the policy timestamp after PCM work so an interval change cannot
  interpret an earlier timestamp as nearly a full timer wrap of source credit.
- Reject an unowned route before reading PCM, preserving its source and timing.
- Preserve the current ten-second button/app takeover request through passive
  old-owner reports, while clearing stale ownership and confirmation. Fresh
  positive ownership evidence is still required before playback. Expiry and a
  newer explicit remote takeover retain priority.
- Recheck queued takeover intent, the active peer and its original ten-second
  deadline at send time; expiry does not revoke confirmed ownership.
- Negotiate one bounded AVDTP Start for an explicit AAC-ELD takeover before the
  positive source report, while keeping PCM and timers blocked until ownership.
  Preserve the original transition deadline and reject stale peer/session/intent
  callbacks; cancellation or a peer Suspend cannot retry the same request.
- Treat a validated idle-source report as observed state without granting
  ownership. Defer fresh handoff buffer negotiation until owned media is warm:
  pre-media commands can return zero delay and falsely leave Game Mode failed.
  Keep ordinary suspended-stream and microphone restoration gates unchanged.
- Preserve phone-call priority: a reported foreign call cancels pending media
  takeover and blocks another request until a valid noncall report clears it.
- Keep PCM32, codec bandwidth, volume behavior, `.0076` radio policy, manual
  button/app reconnect permission and the existing audio workspace.

The combined candidate passed 78 native sanitizer suites and 202 Python checks,
including exact waveform comparisons, checkpoint cancellation, replacement
clock/PCM protection, send-time takeover expiry and phone relay continuity.
One platform-specific Python check is skipped. Packaging also requires linked
.0076/PCM32 codec and memory validation.

The 0.1.68 arithmetic optimization alone did not stop the reported crackle.
This candidate targets the long interrupt-masked preparation instead. Actual
USB interrupt timing, packet continuity and listening checks are pending.

The first 0.1.69 listening comparison was clean, but its counters exposed one
spurious recovery with 1,288,490,236 frames of discarded credit. A real-poll
regression reproduced that exact stale-timestamp result and passes with the
timestamp refresh. The clock repair subsequently completed both live transitions
cleanly, with no menu error or active PCM loss, inserted silence, debt discard or
timing recovery.

A simultaneous failed-handoff capture showed healthy Windows/USB playback but
no AirPods ownership and a stopped encoder. A regression reproduces cancellation
after OWN or Hijack on a passive old-owner report. The revised handshake still
failed live phone-to-dongle acceptance after reaching Hijack: no positive
ownership evidence arrived before expiry. The Mac capture shows Start/Accept
preceding the local media-source report; the bounded control-Start change follows
that ordering and achieved a user-confirmed first-press takeover with owned
streaming and clean counters. The final idle-source and fresh-handoff buffer
ordering changes still need live acceptance. No USB control-plane or automatic
media-play workaround is included. LibrePods was not changed.
